# RUMBO

Aplicación web para mejorar hábitos, registrar la evolución física y organizar el entrenamiento, con una experiencia visual inspirada en Liquid Glass. Funciona en móvil, tablet y escritorio, en modo oscuro (predeterminado) y claro.

> RUMBO es una herramienta de seguimiento personal, no un dispositivo médico. Las estimaciones de calorías, IMC o distancia son orientativas.

## Puesta en marcha

Requisitos: Node.js 20 o superior.

```bash
npm install
npm run dev        # entorno de desarrollo en http://localhost:5173
npm run build      # build de producción en dist/
npm run preview    # sirve el build en http://localhost:4173
```

### Versión en un solo archivo HTML

```bash
npm run build:html # genera dist-html/rumbo.html
```

`rumbo.html` lo incluye todo (código, estilos, fuente Inter, logotipo e iconos) y funciona al abrirlo directamente desde el disco, sin servidor ni conexión a internet. Usa rutas con `#` (por ejemplo `rumbo.html#/progresos`) y guarda los datos en el navegador como la versión normal. Si el navegador no permite guardar datos (ventanas privadas o visores de archivos), la app sigue funcionando en un **modo temporal** claramente avisado, en el que nada se conserva al cerrar.

Comprobaciones:

```bash
npm run typecheck  # TypeScript estricto
npm run lint       # ESLint (incluye las reglas de React Hooks)
npm test           # pruebas unitarias e integración (Vitest + IndexedDB simulada)
npm run test:e2e   # genera rumbo.html y ejecuta las pruebas end-to-end en móvil y escritorio (Playwright)
```

## Arquitectura

```
src/
  app/          Shell, rutas (carga diferida), tema, splash
  brand/        Logotipo vectorizado a partir de los archivos originales
  db/           Dexie (IndexedDB): esquema versionado, repositorios, hooks reactivos, sincronización de hitos
  domain/       Lógica pura y testeada: fechas locales, unidades, salud, peso, hábitos, entrenamiento, hitos
  features/     Pantallas por módulo
  styles/       Tokens de diseño, material Liquid Glass, componentes y layout
  ui/           Componentes reutilizables (GlassCard, Button, Field, Sheet, Segmented, ProgressRing…)
e2e/            Pruebas Playwright
```

- **Stack:** React 19, TypeScript estricto, Vite, React Router, Motion, Dexie, d3-shape (curvas), Lucide.
- **Una sola fuente de verdad:** todas las pantallas leen de IndexedDB mediante consultas reactivas, así que registrar un peso actualiza a la vez el inicio, la gráfica, el calendario y los hitos.
- **Fechas:** los registros se guardan por día natural local (`YYYY-MM-DD`), nunca convertidos a UTC, para que nada salte de día.
- **Temporizadores:** el cronómetro y el descanso se calculan con marcas de tiempo, por lo que siguen siendo correctos aunque se cierre la app.
- **Racha diaria** (`src/domain/streak.ts`): un día cuenta como completado cuando tiene al menos un registro real (peso, agua, pasos > 0 o un entreno terminado), la misma definición que usan los hitos. La racha no se guarda como contador: se recalcula a partir de los registros por día local, por lo que recargar, abrir varias pestañas o registrar varias cosas el mismo día nunca la incrementa dos veces, y añadir un dato atrasado la repara. Mientras el día de hoy sigue abierto se muestra la racha que termina ayer; si pasa un día completo sin registros, la racha actual vuelve a 0 y la mejor racha se conserva en el historial. El cambio de día se detecta aunque la app siga abierta. La celebración aparece una sola vez al día (clave `streak:celebrated`) y nunca el día de creación del perfil. Los mensajes animan sin culpa («Haz un registro hoy para llegar a 8 días», «Cualquier registro de hoy enciende la llama…»).
- **Hitos:** se recalculan tras cada cambio. Cada hito se desbloquea una sola vez y solo se retira si se eliminan o corrigen los registros que lo justificaban. Los objetivos de agua y pasos se guardan por día, de modo que cambiar el objetivo no reescribe el pasado. Las condiciones no dependen del paso del tiempo: los retos con medias semanales o con límite superior (ritmo de peso, banda de mantenimiento, días de descanso) solo cuentan semanas ya terminadas, así que nada se desbloquea y retira dentro de la misma semana; «Equilibrio» cuenta cualquier ventana de 28 días que cumplió durante un objetivo de mantenimiento (y conserva la regla original), para que no desaparezca al pasar los días. Seguridad: los hitos de peso premian pesarse cada semana y avanzar a un ritmo gradual (una semana que supere el 1 % del peso corporal corta la racha), nunca la velocidad; los de agua premian cumplir el objetivo (los litros acumulados cuentan como máximo el objetivo de cada día); los de entreno se miden por semanas (2–3 sesiones) y «Descanso Inteligente» premia dejar al menos dos días de descanso; las rachas valen con cualquier registro. Catálogo en `src/domain/achievements/catalog.ts`, métricas en `metrics.ts`, agrupación de la pantalla en `src/features/milestones/model.ts`.

## Cálculos y personalización

- **Sección de Nutrición eliminada:** ya no existe la ruta, el menú ni sus componentes; `/nutricion` redirige a Inicio. Se mantienen el cálculo de calorías (Progresos › Calorías y la tarjeta de Inicio) y las preguntas de hábitos alimentarios del onboarding, que solo se usan para personalizar consejos.
- **IMC** (`src/domain/body.ts`): kg/m² con un decimal a partir de la altura del perfil y el último peso registrado (si hay varios en un día, el último). Categorías para adultos: < 18,5 bajo peso · 18,5–< 25 intervalo de referencia · 25–< 30 sobrepeso · ≥ 30 obesidad. A menores y durante el embarazo no se les asignan categorías de adulto. Siempre se indica que es orientativo y no un diagnóstico.
- **Factor de actividad** (`estimateActivityLevel` en `src/domain/health.ts`): base según cómo pasas el día (sentado 0 · de pie 1 · en movimiento 2; un trabajo físico cuenta como movimiento y uno de pie como de pie) + entrenamiento semanal (0 días +0 · 1–2 +0,5 · 3–4 +1 · 5+ +1,5), redondeado → Sedentario ×1,2 · Ligero ×1,375 · Moderado ×1,55 · Activo ×1,725 · Muy activo ×1,9. El nivel estimado se guarda en el perfil; si se cambia a mano en Perfil, prevalece el elegido.
- **Calorías:** metabolismo basal con Mifflin-St Jeor (10·kg + 6,25·cm − 5·edad + 5 en hombres / −161 en mujeres; valor intermedio si no se indica el sexo) × factor de actividad = mantenimiento. Objetivos moderados según la meta: pérdida suave ≈10 % (máx. 300 kcal, recomendado) o gradual ≈20 % (máx. 500 kcal); recomposición ≈10 % opcional; ganancia suave ≈5 % (máx. 200 kcal) o gradual ≈10 % (máx. 350 kcal). Ningún objetivo baja del metabolismo basal. Menores, embarazo o lactancia, antecedentes de TCA, condiciones médicas y adultos con IMC < 18,5 solo ven el mantenimiento como referencia y una recomendación de consultar a un profesional. Ejemplo verificado en las pruebas: hombre de 28 años, 180 cm, 85,4 kg, sentado y 3 entrenos → basal 1.844, ×1,375 → mantenimiento 2.540, objetivo 2.280 kcal.
- **Ajustar el cálculo** (Progresos › Calorías): edita peso, altura, edad, sexo, nivel de actividad, objetivo, el objetivo calórico entre los que se ofrecen y el reparto de macros. Valida vacíos, valores no numéricos, negativos y fuera de rango con mensajes accesibles; al guardar (`applyCalculation`, una sola transacción) actualiza el perfil, registra un peso distinto como el peso de hoy (corrige el último de hoy en vez de duplicarlo) y añade la estimación al historial, así que la tarjeta de calorías, los consejos y el resto de la app cambian al instante y tras recargar. El objetivo elegido solo se aplica mientras siga siendo el mismo objetivo del perfil. Las fórmulas no cambian.
- **Consejos personalizados** (`src/domain/tips`, `src/features/tips`): motor de reglas sin IA ni llamadas externas. Construye un contexto solo con datos reales (objetivo, tendencia de peso de 14 días, días sin registros, agua, pasos y entreno de hoy, cumplimiento de los últimos 7 días, racha, actividad, respuestas de alimentación, motivación y bienestar, edad y avisos de salud, antigüedad de los datos del perfil). 40 plantillas con condiciones y prioridad; se elige **un consejo principal al día**, estable durante todo el día, sin repetir consejos de los últimos 7 días si hay alternativa, y como mucho un «Un paso más» si ocurre un cambio significativo (primer registro tras 3 días o más, todos los objetivos del día cumplidos, entreno terminado, objetivo de peso alcanzado). Un filtro de seguridad rechaza palabras prohibidas, rutas inexistentes y consejos de peso para menores o con avisos de salud. Se guarda en el dispositivo (`tips:day:<fecha>`, `tips:history`, con limpieza automática). Las fuentes de consejos siguen una interfaz (`TipSource`) para poder añadir más adelante una fuente generada por IA sin tocar la interfaz.

- **Rumbi flotante** (`src/features/assistant`): Rumbi acompaña en todas las pantallas como un botón flotante al estilo de AssistiveTouch del iPhone. Se arrastra con el dedo o el ratón (resiste si se lleva fuera de la pantalla), al soltarlo se acopla con un muelle al borde más cercano (o al que apunte un gesto rápido) y recuerda el sitio (`rumbo.rumbi` en este dispositivo: lado y altura relativa, así sobrevive a giros y tamaños de pantalla). Siempre queda entre la cabecera y la barra de navegación, por encima del temporizador de descanso y de los avisos, y a la derecha de la barra lateral en escritorio. Tras unos segundos sin tocarlo, o al desplazarse, se esconde a medias en el borde, se atenúa y se queda quieto; se aparta con los diálogos y con el teclado del móvil. Se mueve también con las flechas del teclado. Al pulsarlo abre su panel: saludo y una frase manuscrita construida con los registros de hoy (racha, objetivos cumplidos, entreno; tocar a Rumbi cambia de frase), **Tu consejo de hoy**, **consejos por tema** (hábitos, constancia, descanso, entreno y progreso, elegidos por el mismo motor de reglas con los datos reales y con un consejo general si no aplica ninguno), atajos (registrar peso o pasos, +250 ml de agua, entrenar, hitos) y la ayuda que ya existe (cálculo de calorías, IMC, objetivo, datos y copias, uso responsable). Celebra con un pequeño salto cuando se guarda un registro o se termina un entreno (`src/ui/cheer.ts`). Se activa o desactiva en Perfil › Apariencia (o «Ocultar a Rumbi» en su panel, con deshacer).
- **Rumbi, la mascota** (`src/features/mascot`): una esfera brillante con ojos en forma de píldora que toma el color de acento. Es quien da «Tu consejo de hoy» y cambia de expresión según el consejo (neutral, contenta, orgullosa, animando, pensando mientras carga, con sueño de noche, atenta con el estrés y sorprendida cuando llega un «Un paso más»). Toda la animación es JavaScript con muelles: transición fluida entre expresiones, parpadeo natural, respiración, miradas, sigue el dedo o el cursor y reacciona al tocarla. Se pausa fuera de pantalla o con la pestaña oculta y respeta `prefers-reduced-motion`.

## Diseño

- **Identidad (violeta):** negros profundos con un leve tinte del acento y tres niveles de superficie (tarjeta, tesela interior, elevada) separados por luz más que por bordes; texto blanco; degradados violeta → lavanda para la marca, la acción principal, la navegación y el progreso; verde, ámbar y rojo solo para estados (cumplido, intermedio, desfavorable). Tarjetas mates con un filo de luz y sombras discretas; el desenfoque se reserva para lo que flota sobre el contenido (barras de navegación, hojas). Las pestañas internas usan una lente de alto contraste (blanca en oscuro, tinta en claro) para que el violeta quede para la navegación principal y las acciones. El modo claro no es una inversión: papel lavanda muy suave, paneles blancos con sombras suaves, tinta casi negra y el violeta como relleno con texto blanco. VIOLETA RUMBO es el acento por defecto: las instalaciones que seguían con el acento por defecto anterior (lima) pasan a él una vez; un acento elegido por el usuario se respeta. Ajustes de identidad en `src/styles/identity.css`.
- **Tipografías** (`src/styles/fonts.css`, servidas desde la propia app en WOFF2 + WOFF con `font-display: swap`), con tres papeles: la **sans-serif del sistema** (SF Pro en Apple, Inter en el resto) para todo lo que se lee o se usa (textos, cifras, botones, formularios, navegación); **Krophed**, la fuente del logotipo, para el título de marca de cada sección (PROGRESO, ENTRENO, HITOS…, con degradado violeta), y el título del panel de Rumbi, solo cuando puede componer el texto completo (no tiene tildes, ñ, ¿ ni ¡; `src/brand/krophed.ts` lo comprueba); **212 Baby Girl** para notas manuscritas breves («tu ritmo, tu rumbo», «poco a poco, suma», la firma de ¿Quién soy?); con moderación. Escala responsive en `tokens.css` (`--fs-brand` 24 → 34 px, `--fs-title` 19 → 24 px, `--fs-greet` 28 → 40 px, `--fs-section` 17 → 20 px, `--text-hero` 44 → 60 px): los títulos de sección ya no ocupan el ancho de la pantalla y dejan sitio al contenido. Ninguna serif. A Krophed solo se le corrigió la caja delimitadora declarada (Chrome recortaba la O, M o W a tamaños grandes); los glifos no se tocan.
- **Mapa muscular** (`src/domain/training/anatomy.ts` + `src/features/training/bodymap/`): 17 regiones con id estable (pectorales; trapecio, dorsales y zona lumbar; deltoides anterior, lateral y posterior; bíceps, tríceps y antebrazos; abdominales y oblicuos; glúteos; cuádriceps; aductores; isquiotibiales; gemelos y sóleo), cada una con nombre visible, grupo, vistas en que aparece y ejercicios relacionados. Los 68 ejercicios de fuerza del catálogo tienen sus motores principales y secundarios definidos uno a uno; los personalizados usan su grupo (y sus secundarios) y el mapa avisa de que el detalle es aproximado; cardio, movilidad y recuperación no colorean músculos y se indica. El color sale **solo de las series reales**: sólido para principal, más suave para secundario, contorno para lo pendiente o planificado y tres niveles semanales (menos de 4, 4–9 y 10 o más series; las secundarias cuentan media). Nunca se usa el nombre de la rutina ni se marca nada como hecho por mirar el mapa. Las figuras masculina, femenina y neutra comparten las mismas formas, reproporcionadas (hombros, cintura, cadera, brazos y pecho), así que ids y comportamiento no cambian entre ellas. En móvil se ve una figura con interruptor Frente/Espalda (gira al cambiar) y en pantallas anchas ambas a la vez; cada músculo se toca, se recorre con el teclado (flechas) y tiene nombre accesible con su estado. Respeta `prefers-reduced-motion`.
- **¿Quién soy?:** iconos lineales monocromos blancos propios para Instagram, TikTok y YouTube sobre una tesela oscura; cada tarjeta es un enlace real con nombre accesible, foco visible y estados suaves.
- Tokens en `src/styles/tokens.css` (colores de marca, espaciado de 4 pt, radios, desenfoques, duraciones). Cada tema define sus propios roles.
- Material en `src/styles/glass.css` (afinado en `identity.css`): borde luminoso degradado, reflejo especular que sigue al cursor y un barrido de brillo sutil en las superficies principales; desenfoque real solo en navegación y hojas. En dispositivos de poca potencia (o con «Efectos ligeros») se sustituye el desenfoque por superficies sólidas.
- El cambio de tema usa la View Transitions API con un revelado circular desde el botón; sin soporte, transición de color suave. El tema se aplica antes del primer pintado para evitar destellos.
- **Color de la interfaz:** seis paletas de acento (VIOLETA RUMBO, ROJO INTENSO, NARANJA BRASA, LIMA VOLT, CIAN GLACIAR y FUCSIA NEÓN), desde el botón de la barra superior o Perfil → Apariencia. Cada paleta define una pequeña rampa en `tokens.css` (incluido un tono pálido para degradados) de la que ambos temas derivan sus colores, y tiñe levemente fondos y superficies; los colores de estado (verde, ámbar, rojo) no cambian. Se guarda en el dispositivo y se aplica antes del primer pintado.
- **Fondo interactivo:** auroras de color en movimiento y una cuadrícula de puntos (canvas) casi invisible en reposo (no compite con el texto) que se ilumina alrededor del dedo o el cursor como una lente líquida, con onda expansiva al tocar. Visto a través del cristal se percibe como refracción. Solo se anima mientras hay movimiento y se desactiva con «Efectos ligeros» o `prefers-reduced-motion` (`src/app/shell/AppBackground.tsx`).
- **Lenguaje de interacción común** (`src/styles/interaction.css`): al pulsar, todo control se hunde en ~90 ms y vuelve con un muelle suave (~340 ms), con tres profundidades (iconos, botones/chips/opciones, tarjetas). Las pestañas animan el icono, los controles segmentados atenúan la etiqueta (su indicador ya se desliza), las filas de menú se atenúan y el interruptor estira su mando. El *hover* solo existe con puntero real. Con movimiento reducido se mantiene el aviso visual (opacidad) sin desplazamiento.
- **Transiciones entre pantallas:** la pantalla saliente se retira en 120 ms y la nueva entra en cascada con un muelle críticamente amortiguado (~300 ms); no bloquean la interacción.
- **Microinteracciones:** anillos y barras se rellenan con suavidad al cambiar los datos y las cifras cuentan hasta su valor; al completar un objetivo diario con la pantalla abierta, el anillo lanza una onda suave y aparece «Hecho»; al guardar un registro o terminar un entreno, Rumbi da un pequeño salto; los hitos y la racha tienen su celebración. Todo respeta `prefers-reduced-motion`.
- **Cabecera:** al desplazarse, el nombre de la sección aparece junto al logotipo en MAYÚSCULAS (etiqueta corta en móviles estrechos). Los nombres salen de una única fuente (`src/app/nav.ts`) y no cambian las rutas.
- **Racha:** llama vectorial propia de estilo clásico (lengua principal con la punta curvada, dos lenguas laterales y núcleo amarillo con su propia lengua) con brillo ambiental suave detrás. Tres bucles CSS lentos de periodos distintos (respiración con leve elevación 3,7 s, núcleo 2,3 s, brillo 5,3 s) dan un movimiento orgánico sin saltos; las llamas pequeñas de la semana son estáticas.
- **Liquid Glass en todo:** además de tarjetas, barras y hojas, cada control (pestañas, chips, campos, botones, avisos) se dibuja como una pequeña lente con borde luminoso; los que están sobre el fondo también lo desenfocan.
- Colores de datos validados para daltonismo (peso en tinta neutra, agua azul, pasos ámbar, entrenos con forma de anillo); los estados verde/amarillo/rojo siempre van acompañados de icono y texto.

## Privacidad y datos

Los datos se guardan únicamente en el navegador del dispositivo (IndexedDB). No hay servidor, cuentas ni claves en el cliente. La foto de perfil se prepara en el propio dispositivo (cuadrada, 320 px, JPEG) y se guarda con el resto del perfil; solo sale de él dentro de las copias que el usuario exporte, y al importar se aceptan únicamente imágenes JPEG, PNG o WebP incrustadas de tamaño razonable. Desde **Perfil → Datos y privacidad** se puede exportar una copia en JSON, restaurarla o borrar todos los datos. Las copias se validan fila a fila antes de restaurarse, y si una sección fallara al mostrarse aparece un aviso con «Reintentar» (y, si falla toda la app, la opción de descargar una copia de los datos) en lugar de una pantalla en blanco.

## Publicar en Netlify u otro hosting

`npm run build` genera `dist/`. Incluye `public/_redirects` (`/* /index.html 200`) para que las rutas como `/habitos` funcionen al recargar o al abrir un enlace directo en Netlify; en otros servicios hay que configurar la misma regla de *fallback* a `index.html`.

## Pendiente / dependencias externas

- **Sincronización entre dispositivos:** requiere un backend con autenticación (por ejemplo, Supabase con políticas RLS por usuario). El esquema de Dexie está versionado y el formato de exportación sirve de base para migrar.
- **Apple Salud / Health Connect / relojes:** no disponibles en web; los pasos se registran manualmente.
- **Notificaciones y consejos programados:** no implementados (no hay backend ni procesos en segundo plano; los consejos se eligen solo mientras la app está abierta). Harían falta: un backend con cuentas y consentimiento explícito para enviar un resumen mínimo y anonimizado del contexto; una tarea programada en el servidor que reutilice las mismas reglas de seguridad; un service worker, permiso de notificaciones pedido tras una acción del usuario, envío push desde el servidor, registro de suscripciones por dispositivo y ajustes de horario silencioso y límite diario. En iOS, las notificaciones web solo funcionan con la app añadida a la pantalla de inicio, y la versión en un solo archivo HTML abierta desde el disco no puede tener service worker.
- **Registro de entrenamiento ampliado y guías animadas de ejercicios:** pendiente (no incluido en esta entrega).
